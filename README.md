# ระบบจัดการสินค้าและ QR Code

เว็บหลังบ้านสำหรับจัดการสินค้า (เพิ่ม/แก้ไข/ลบ, Import จาก Excel, อัปโหลดรูป, สร้าง QR Code) พร้อมหน้าสินค้าสาธารณะที่ลูกค้าเปิดได้จากการสแกน QR และมีระบบบันทึกการสแกนกับการแยกสิทธิ์ผู้ดูแลระบบ 2 ระดับ

## 1. วิธีติดตั้งและรันระบบ

### สิ่งที่ต้องมีในเครื่อง

- [Node.js](https://nodejs.org) 20.9 ขึ้นไป
- [Docker Desktop](https://www.docker.com/products/docker-desktop) (เปิดโปรแกรมทิ้งไว้ ใช้รัน PostgreSQL)
- พอร์ต `3000` (เว็บ) และ `5433` (ฐานข้อมูล) ต้องว่าง

> ผู้พัฒนาทดสอบบน **macOS (Apple Silicon)** กับ Node 22 และ Docker 28 เท่านั้น Windows และ Linux ยังไม่ได้ทดสอบ

### ขั้นตอน

```bash
git clone https://github.com/Nsybluu/yes-dev-test.git
cd yes-dev-test
npm install
npm run setup
npm run dev
```

จากนั้นเปิด <http://localhost:3000> (จะพาไปหน้า Login)

`npm run setup` ทำให้ในคำสั่งเดียว: สร้างไฟล์ `.env` (รหัสผ่านและ secret สุ่มใหม่), เปิด PostgreSQL ใน Docker, สร้างตารางด้วย migration และสร้างบัญชี Super Admin คนแรก เมื่อเสร็จจะแสดงอีเมลและรหัสผ่านบนหน้าจอ รันซ้ำได้โดยไม่ทับของเดิม

### บัญชี Super Admin สำหรับทดสอบ

|          |                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| อีเมล    | `superadmin@example.com`                                                                                                        |
| รหัสผ่าน | **สุ่มใหม่ทุกครั้งที่ติดตั้ง** แสดงบนหน้าจอตอน `npm run setup` จบ และเก็บไว้ในไฟล์ `.env` ที่ตัวแปร `SEED_SUPER_ADMIN_PASSWORD` |

ดูรหัสผ่านย้อนหลังได้ด้วย (macOS/Linux) `grep SEED_SUPER_ADMIN .env` หรือ (Windows PowerShell) `Select-String SEED_SUPER_ADMIN .env`

- ไม่มีหน้าสมัครสมาชิก (ตามโจทย์) ผู้ใช้คนแรกมาจาก `setup` เท่านั้น
- **บัญชี Admin** สร้างได้ที่เมนู "จัดการผู้ใช้" → เชิญ → กด "คัดลอกลิงก์เชิญ" → เปิดลิงก์ในหน้าต่างไม่ระบุตัวตน (Incognito) เพื่อตั้งรหัสผ่านและเข้าใช้งานในฐานะ Admin (ถ้าเปิดในเบราว์เซอร์เดียวกัน การเปิดลิงก์เชิญจะเข้าระบบทับ session เดิม) อีเมลคำเชิญไม่ได้ส่งจริง แต่ถูกบันทึกลงหน้าจอ terminal ของ `npm run dev`
- ถ้าอยากตั้งรหัสผ่านเอง แก้ `SEED_SUPER_ADMIN_PASSWORD` ใน `.env` แล้วเริ่มใหม่ด้วย `docker compose down -v`, ลบ `.env`, รัน `npm run setup` (ฐานข้อมูลจะถูกล้าง)

### ลองใช้งานตามลำดับนี้

1. **นำเข้า Excel** เมนู "นำเข้า Excel" มีไฟล์ตัวอย่างในโฟลเดอร์ [`sample-data/`](sample-data):
   - `products-valid.xlsx` ข้อมูลถูกต้องทุกแถว นำเข้าทันทีและขึ้น Success Popup
   - `products-with-problems.xlsx` (นำเข้าไฟล์แรกก่อน) แสดงปัญหาทุกชนิด: ข้อมูลหาย, ผิดชนิดข้อมูล, ค่าไม่ถูกต้อง, SKU ซ้ำในไฟล์, SKU พิมพ์เล็ก (ระบบแก้ให้), แถวว่าง และ SKU ซ้ำกับในระบบ (เปรียบเทียบค่าเดิม/ใหม่ แล้วเลือกเขียนทับหรือข้าม)
   - ใช้ไฟล์ของโจทย์ได้เช่นกัน (หัวคอลัมน์: `sku, name, category, price, size, description, how_to_use, status`)
2. **สินค้า** ค้นหา, กรองสถานะ, กดหัวคอลัมน์ SKU/ชื่อ/ราคาเพื่อเรียงลำดับ, เพิ่ม/แก้ไข/ลบ ในหน้าแก้ไขมีส่วนอัปโหลดรูปหลักกับรูป Gallery และรูป QR พร้อมปุ่มดาวน์โหลด
3. **หน้าสินค้าสาธารณะ** กดลิงก์ใต้รูป QR ในหน้าแก้ไขสินค้า (นับเป็นการสแกน) แล้วดูหน้าที่ลูกค้าเห็น ลองย่อหน้าต่างให้แคบเพื่อดูแบบมือถือ
4. **สถิติการสแกน** เมนู "สถิติการสแกน" และแดชบอร์ด แสดงสินค้าที่ถูกดูมากที่สุด

### ทดสอบสแกน QR ด้วยมือถือ

QR ฝังลิงก์ตาม `APP_URL` ใน `.env` ซึ่งเริ่มต้นเป็น `http://localhost:3000` ลิงก์นี้เปิดได้เฉพาะในเครื่องที่รันระบบ **มือถือสแกนแล้วจะเปิดไม่ได้** (ระบบแสดงกรอบเตือนสีเหลืองไว้) เลือกวิธีใดวิธีหนึ่ง:

- **ไม่ใช้มือถือ:** ในหน้าแก้ไขสินค้า ใต้รูป QR มีลิงก์ที่ฝังอยู่ กดเปิดได้เลย (ผลเหมือนสแกน)
- **มือถือใน Wi-Fi เดียวกับคอมพิวเตอร์:**
  1. หา IP ของเครื่อง (macOS: `ipconfig getifaddr en0`, Windows: `ipconfig`)
  2. แก้ `.env` เป็น `APP_URL="http://<IP ของเครื่อง>:3000"`
  3. รัน `npm run build` แล้ว `npm run start:lan`
  4. **ดาวน์โหลด QR ใหม่** (QR ที่ได้ก่อนหน้ายังชี้ไป localhost) แล้วสแกนจากหน้าจอ ถ้าเปิดไม่ได้ให้ตรวจ Firewall
- **ผ่านอินเทอร์เน็ต:** ใช้ tunnel เช่น `npx cloudflared tunnel --url http://localhost:3000` ได้ลิงก์ `https://...` มาใส่ `APP_URL` แล้วดาวน์โหลด QR ใหม่

> **แก้ `.env` หรือโค้ดแล้วไม่เห็นผล?** โหมด `npm start` / `start:lan` อ่าน `.env` และโค้ดที่ build ไว้ **ครั้งเดียวตอนเริ่ม** ต้องหยุด (Ctrl+C) แล้วรัน `npm run build && npm run start:lan` ใหม่ทุกครั้งที่แก้ (โหมด `npm run dev` ก็ต้องเริ่มใหม่เมื่อแก้ `.env`) และถ้าสแกนแล้วเปิดไม่ได้ ให้ตรวจว่า QR ที่ใช้เป็นอันที่ดาวน์โหลดหลังแก้ `APP_URL` และ Firewall ของเครื่องไม่บล็อกพอร์ต 3000

> โดเมนจริงยังไม่ได้กำหนด QR ที่พิมพ์ติดสินค้าจริงต้องสร้างหลังตั้ง `APP_URL` เป็นโดเมนที่จะไม่เปลี่ยนอีก

### คำสั่งที่ใช้บ่อย

| คำสั่ง                              | ทำอะไร                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `npm run dev`                       | รันโหมดพัฒนา                                                             |
| `npm test`                          | รันเทสต์ (57 ข้อ เฉพาะตรรกะที่เป็นฟังก์ชันล้วน ดูหัวข้อ 3)               |
| `npm run build` / `npm start`       | build และรันโหมด production                                              |
| `npm run db:up` / `npm run db:down` | เปิด / ปิดฐานข้อมูล (ข้อมูลยังอยู่)                                      |
| `npm run db:studio`                 | เปิดดูข้อมูลในฐานข้อมูล                                                  |
| `npm run db:seed:samples`           | เพิ่มสินค้าตัวอย่าง 5 ชิ้น (ลบด้วย `npm run db:seed:samples -- --clean`) |

### ไม่มี Docker?

ติดตั้ง PostgreSQL เอง คัดลอก `.env.example` เป็น `.env` แล้วใส่ `DATABASE_URL`, `SESSION_SECRET` (ข้อความสุ่มยาวๆ) และ `SEED_SUPER_ADMIN_PASSWORD` จากนั้นรัน `npx prisma migrate deploy` และ `npm run db:seed` แทน `npm run setup`

### แก้ปัญหาเบื้องต้น

- **`Docker is not running`** เปิด Docker Desktop แล้วรัน `npm run setup` ซ้ำ
- **พอร์ตชน** ฐานข้อมูลใช้ 5433 (แก้ที่ `POSTGRES_PORT` และ `DATABASE_URL` ใน `.env`) เว็บใช้ 3000 (`npm run dev -- -p 3001`)
- **ลืมรหัสผ่าน / ล็อกอินไม่ได้** ดูค่าใน `.env` หรือเริ่มใหม่ตามหัวข้อบัญชีทดสอบข้างบน (ระบบยังไม่มีหน้าเปลี่ยน/รีเซ็ตรหัสผ่าน)
- **login หลุดเอง** cookie `session` ใช้ร่วมกันทุกพอร์ตของ `localhost` ถ้ารันโปรเจกต์อื่นพร้อมกันอาจถูกทับ

## 3. ฟีเจอร์ที่ทำเสร็จ และที่ไม่เสร็จ

### ทำเสร็จแล้ว

**ระบบผู้ใช้และสิทธิ์**

- Login ด้วยอีเมล/รหัสผ่าน (ไม่มีหน้าสมัครสมาชิก) session เป็น cookie ที่ลงลายเซ็น (httpOnly, 7 วัน) และตรวจบัญชี/บทบาทจากฐานข้อมูลทุกคำขอ ผู้ที่ถูกลบหรือถูกลดสิทธิ์จึงมีผลทันที
- 2 บทบาท บังคับสิทธิ์ที่ฝั่ง server (การซ่อนปุ่มในหน้าเว็บเป็นแค่ความสะดวก):

  |                                      | Super Admin                                              | Admin                         |
  | ------------------------------------ | -------------------------------------------------------- | ----------------------------- |
  | จัดการสินค้า / Import / QR / ดูสถิติ | ✅                                                       | ✅                            |
  | เชิญผู้ใช้ใหม่                       | ✅                                                       | ❌                            |
  | แก้ไขผู้ใช้                          | ✅ ชื่อ, อีเมล, บทบาทของทุกคน (เปลี่ยนบทบาทตัวเองไม่ได้) | แก้ได้เฉพาะ **ชื่อของตัวเอง** |
  | ลบผู้ใช้                             | ✅ (ลบตัวเองและ Super Admin คนสุดท้ายไม่ได้)             | ❌                            |
  | ล้างสินค้าทั้งหมด                    | ✅                                                       | ❌                            |

  Admin เห็นหน้า "ผู้ใช้" แต่ไม่เห็นอีเมลของคนอื่น

- **เชิญ Admin:** Super Admin ใส่ชื่อและอีเมล ระบบสร้างลิงก์ใช้ได้ครั้งเดียว หมดอายุ 48 ชั่วโมง (เก็บเฉพาะ hash ของ token) และ "ส่งอีเมล" โดยบันทึกลง log ของเซิร์ฟเวอร์ตามที่โจทย์อนุญาต ผู้ถูกเชิญตั้งรหัสผ่านเองที่หน้า `/invite/<token>` มีปุ่มส่งลิงก์ใหม่และปุ่มคัดลอกลิงก์ในหลังบ้าน (แสดงเสมอเพราะยังไม่ได้ส่งอีเมลจริง ซ่อนได้ด้วย `SHOW_INVITE_LINK="false"` ใน `.env` เมื่อส่งอีเมลจริงแล้ว)

**สินค้า**

- รายการสินค้า: ค้นหา SKU/ชื่อ, กรองสถานะ, เรียงลำดับด้วยการกดหัวคอลัมน์ SKU/ชื่อ/ราคา (เรียงที่ฐานข้อมูล ใช้กับทุกหน้า), แบ่งหน้า 20 รายการ, แสดงจำนวนครั้งที่ถูกเข้าดูของแต่ละสินค้า
- เพิ่ม / แก้ไข / ลบ (มี dialog ยืนยันก่อนลบ) ใช้กฎตรวจสอบข้อมูลชุดเดียวกับ Import
- **ล้างสินค้าทั้งหมด** (Super Admin) ยืนยัน 3 ชั้น: ติ๊กรับทราบ → พิมพ์ข้อความ → กรอกรหัสผ่านของตัวเอง ลบไฟล์รูปบนดิสก์ด้วย
- **อัปโหลดรูป:** รูปหลัก 1 รูป + รูป Gallery (รวมไม่เกิน 8 รูป), ตั้งรูปใดเป็นรูปหลัก, ลบรูป รองรับ JPG/PNG/WEBP ไม่เกิน 2 MB ตรวจจากเนื้อไฟล์จริง (ไม่เชื่อนามสกุล) ปฏิเสธพร้อมเหตุผลรายไฟล์ ภาพที่ไม่ใช่สี่เหลี่ยมจัตุรัสหรือเล็กกว่า 800×800 px รับแต่เตือน สินค้าที่ไม่มีรูปแสดง Placeholder

**Import Excel** (`.xlsx` ไม่เกิน 1,000 แถว / 2 MB)

- Flow: อัปโหลด → ตรวจสอบ → สรุป → ยืนยัน ถ้าไฟล์ผ่านทุกแถว (ไม่มีปัญหา ไม่ซ้ำ ไม่มีการแก้อัตโนมัติ) นำเข้าทันทีและขึ้น Success Popup
- สรุปปัญหาแยกชนิด: ข้อมูลหาย, ผิดชนิดข้อมูล, รูปแบบ/ค่าไม่ถูกต้อง, SKU ซ้ำในไฟล์ โดยบอกเลขแถวที่ตรงกับ Excel, คอลัมน์, ค่าที่พบ และเหตุผล แถวเดียวที่ผิดหลายจุดจะรายงานทุกจุด
- แก้ให้อัตโนมัติเฉพาะที่ความหมายชัดเจน: SKU/หมวดหมู่/status พิมพ์เล็ก-ใหญ่, สัญลักษณ์ในราคา (`฿1,290`) ส่วนค่าที่กำกวมเช่น status `yes` ถือเป็นข้อผิดพลาด
- SKU ซ้ำกับในระบบ: เปรียบเทียบค่าเดิม/ค่าใหม่ทีละช่อง เลือกเขียนทับหรือข้าม (รายแถวหรือทั้งหมด) ช่องที่ว่างใน Excel ไม่ลบข้อมูลเดิม และ `productId` ไม่เปลี่ยน
- แถวที่ผ่านถูกนำเข้า แถวที่มีปัญหาถูกข้าม อัปโหลดไฟล์เดิมซ้ำได้อย่างปลอดภัย ตรวจซ้ำตอนยืนยันและเขียนในทรานแซกชันเดียว

**QR Code**

- ทุกสินค้ามี QR ทันทีที่ถูกสร้าง (ไม่ต้องเก็บไฟล์ สร้างตอนขอ) ดาวน์โหลดเป็น PNG จากปุ่มในรายการ (ก่อนปุ่มแก้ไข ได้ไฟล์มาตรฐาน พื้นขาว 1024×1024 px) และจากหน้าแก้ไขสินค้า
- **ปรับแต่ง QR ในหน้าแก้ไขสินค้า:** เปลี่ยน **สีพื้นหลัง** (สีสำเร็จรูปหรือเลือกเอง) และ **ขนาด** (800 / 1024 / 1500 / 2000 / 3000 / 4000 px) มีรูปตัวอย่างที่เปลี่ยนตามทันที แล้วดาวน์โหลดเป็น PNG ตัว QR เป็นสีดำเสมอ และไม่ให้เลือกพื้นหลังที่เข้มเกินไปเพราะจะสแกนไม่ได้ (บังคับที่ฝั่ง server ด้วย)
- QR ฝังลิงก์ `APP_URL/p/<productId>` ไม่ฝังข้อมูลสินค้า `productId` ไม่เปลี่ยนเมื่อแก้ไขสินค้า QR ที่พิมพ์แล้วจึงยังใช้ได้และแสดงข้อมูลล่าสุดเสมอ QR จะใช้ไม่ได้เมื่อลบสินค้าเท่านั้น

**หน้าสินค้าสาธารณะ** (`/p/<productId>`)

- ออกแบบสำหรับมือถือก่อน บน desktop แบ่ง 2 คอลัมน์ มีแกลเลอรี (รูปย่อ, ลูกศร, ปัดนิ้ว), ขั้นตอนวิธีใช้แบบมีเลขข้อ, ส่วน "สินค้ายอดนิยม"
- สินค้า `inactive` หรือที่ไม่มีอยู่ ขึ้นหน้า "ไม่พบสินค้า" (HTTP 404) เหมือนกัน หน้านี้ query เฉพาะ field ที่ลูกค้าควรเห็น

**บันทึกการสแกน**

- บันทึกทุกครั้งที่มีคนเปิดหน้าสินค้า (QR คือลิงก์เดียวกัน) เก็บเวลากับ user agent ไม่เก็บ IP บันทึกหลังส่งหน้าเสร็จ การบันทึกล้มจึงไม่กระทบลูกค้า
- ไม่นับ: บอต/ตัวพรีวิวลิงก์, การโหลดล่วงหน้าภายในของ Next และปุ่ม "ดูตัวอย่างหน้าสาธารณะ" ในหลังบ้าน (`?preview=1`)
- หน้า "สถิติการสแกน" (10 อันดับ, รายการล่าสุด, กรองทั้งหมด/30/7 วัน) และสรุปบนแดชบอร์ด

**อื่นๆ**

- `npm run setup` ติดตั้งคำสั่งเดียว, ไฟล์ Excel ตัวอย่าง, สินค้าตัวอย่าง (`db:seed:samples`)
- unit test 57 ข้อ ครอบคลุม: กฎตรวจสอบสินค้า, ตัววิเคราะห์ไฟล์ Import (จัดกลุ่มแถว, SKU ซ้ำ, ช่องว่างไม่ลบข้อมูล), ตัวตรวจไฟล์ภาพ, กฎนับสแกน, token/รหัสผ่านของคำเชิญ, กฎสิทธิ์แก้ไข/ลบผู้ใช้, การเรียงลำดับรายการสินค้า, การอ่านค่า `APP_URL`, กฎสี/ขนาด QR

### ยังไม่เสร็จ และข้อจำกัดที่รู้

**ฟีเจอร์ที่ไม่ได้ทำ**

- **ส่งอีเมลจริง** (Mailtrap/SMTP) ตอนนี้บันทึกลง log เท่านั้น (เปลี่ยนที่ฟังก์ชัน `sendEmail` ใน [`lib/email.ts`](lib/email.ts) ที่เดียว)
- **สถิติสแกน:** แยก "สแกนจาก QR" ออกจาก "เปิดลิงก์เอง" ไม่ได้ (เป็น URL เดียวกัน) ไม่กันการรีเฟรชซ้ำ (ตามโจทย์ "ทุกครั้งที่เปิด") และในโหมด dev การโหลดหน้าซ้ำของ Fast Refresh ก็ถูกนับ

**ความปลอดภัยที่ยังขาด**

- ไม่มี rate limit / ล็อกบัญชีเมื่อใส่รหัสผ่านผิดซ้ำ ทั้งหน้า Login และขั้นยืนยันรหัสผ่านของ "ล้างสินค้าทั้งหมด"
- ยังไม่มีการตั้งค่าสำหรับ production จริง (โดเมน, HTTPS, ที่เก็บไฟล์รูป, ส่งอีเมล)

**การทดสอบ**

- มีเฉพาะ unit test ของตรรกะที่เป็นฟังก์ชันล้วน **ไม่มี** integration/E2E test อัตโนมัติ ส่วน UI และ Server Actions ตรวจโดยการทดลองใช้งานและสคริปต์สั่งเบราว์เซอร์ในช่วงพัฒนา ไม่ได้เก็บเป็นเทสต์
- ยังไม่ได้ deploy ขึ้นเซิร์ฟเวอร์ และทดสอบบน macOS เท่านั้น

## 5. การใช้ AI

### เครื่องมือที่ใช้

Claude Code (แอป Claude desktop) ด้วยโมเดล Claude Sonnet 5.5 ใช้แบบสนทนาต่อเนื่องในโฟลเดอร์โปรเจกต์ AI อ่าน/เขียนไฟล์ รันคำสั่ง (npm, Prisma, Docker, psql, curl) และควบคุมเบราว์เซอร์ในแอปเพื่อทดลองใช้งานเว็บที่ตัวเองเขียนได้

### ใช้ทำอะไรบ้าง

ให้ AI ช่วยวิเคราะห์แผนที่คิดไว้ และบอกข้อดีข้อจำกัดของแผนที่วางไว้ และให้ Coding ไปประมาณ 80% เลย

งานที่ให้ AI ทำ:

- วิเคราะห์ `Plan.md` และตรวจสอบ schema ฐานข้อมูลที่วางไว้ (AI ชี้ว่า Admin ขาด email/password/ข้อมูลคำเชิญ และขาดตารางบันทึกสแกน)
- สร้างโครงโปรเจกต์ ตั้ง Docker/Prisma/migration ตั้งค่า shadcn/ui และสคริปต์ `npm run setup`
- เขียนระบบ Login/สิทธิ์, CRUD สินค้า, Import Excel พร้อมตัวตรวจสอบ, อัปโหลดรูป, QR, หน้าสินค้าสาธารณะ, บันทึก/สถิติการสแกน, เชิญและจัดการผู้ใช้
- เขียน unit test และสั่งทดลองใช้งานผ่านเบราว์เซอร์ในแอป รวมถึงจำลองการติดตั้งบนเครื่องสะอาด
- เป็นที่ปรึกษาเรื่องการออกแบบ (ให้ข้อดีข้อเสียพร้อมคำแนะนำ แล้วผู้พัฒนาเป็นคนเลือก)

สิ่งที่ผู้พัฒนาทำเอง: กำหนดขอบเขตและลำดับความสำคัญ (`Plan.md`), ตัดสินใจเมื่อ AI เสนอทางเลือก (เช่น Import แบบนำเข้าแถวที่ผ่านก่อน, ถาม-ตอบเมื่อ SKU ซ้ำ, เชิญ Admin ด้วยลิงก์ที่บันทึกลง log), ลองใช้งานจริงและรายงานจุดที่ผิด

### ตัวอย่าง prompt (ข้อความจริงจากแชท)

**1. ให้วิเคราะห์แผนก่อนลงมือ**

> อ่านไฟล์ Plan.md และวิเคราะห์ให้ละเอียด หลังจากนั้นสร้างโปรเจค Nextjs ลงใน yes-dev-test เลยไม่ต้องมีสร้างโฟล์เดอร์เพิ่ม โดยสร้างแค่โปรเจคเปล่าๆไว้ก่อน และ บอกสิ่งที่วิเคราะห์ได้จากไฟล์ Plan.md ที่ผมเขียน

ผลที่ได้: AI สร้างโปรเจกต์ และสรุปข้อสังเกต เช่น QR ควรฝังลิงก์ไม่ใช่ข้อมูล, โครง Admin ยังขาด field, ข้อกำหนดที่ขัดกันเรื่องลำดับความสำคัญ ข้อสังเกตเหล่านี้ใช้ต่อในการออกแบบจริง

**2. ให้ประเมินแผนเฉพาะส่วนก่อนเขียนโค้ด**

> ก่อนเริ่มทำอยากให้เจาะไปที่ Database ที่เขียนใน Plan ก่อนว่า ออกมาประมาณนี้เพียงพอสำหรับงานหรือยัง

ผลที่ได้: AI ตอบว่ายังไม่พอ พร้อม schema ฉบับปรับปรุง ผู้พัฒนาส่งรูปแบบคอลัมน์ Excel ตามโจทย์มา AI จึงปรับ schema อีกรอบ schema สุดท้ายมาจากการโต้ตอบ 2 รอบนี้

**3. ให้ตรวจบั๊กที่ผู้พัฒนาพบเอง**

> ตรวจสอบระบบการบันทึก User เข้าดูสินค้า ผมตรวจสอบแล้วเหมือนจะไม่ทำงาน เข้าดูหลายครั้งแล้วแต่หลังบ้านยังขึ้นเป็น 0 อยู่

ผลที่ได้: AI ทดลองยิงคำขอจริงแล้วพบว่าระบบบันทึกทำงานปกติ แต่กติกาที่ AI ตั้งไว้เองทำให้ไม่นับกรณีที่ผู้พัฒนาทดสอบ (ดูหัวข้อ "AI ผิดพลาด")

### AI ผิดพลาดตรงไหน และแก้อย่างไร

ในมุมมอง UI จะทำออกมาเพี้ยนในบางจุดต้องมาปรับแก้เอง และ ในการ prompt ต้องพิมพ์รายละเอียดให้ชัดเจน

**ข้อจำกัดที่ต้องรู้เมื่อเชื่อผลทดสอบ:** ตัวเลขเวลา "ใช้เวลาเท่าไร" ที่ AI เสนอเป็นการประมาณ ผลทดสอบส่วนใหญ่มาจากสคริปต์ที่ AI เขียนและรันเอง

### ส่วนที่ผู้พัฒนาเขียนเองทั้งหมด (ไม่ใช้ AI)

ส่วนใหญ่ผมจะออกแบบแผนและแนวคิด Flow การทำงาน และให้ AI Coding เป็นส่วนใหญ่

Plan.md และ แก้ส่วน UI ที่ AI ทำออกมาและเพี้ยน
